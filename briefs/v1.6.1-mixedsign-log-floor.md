# Brief -- v1.6.1: mixed-sign log-domain floor

Status: PLAN ONLY. Local scratch, not shipped (`briefs/` is not in
package.json `files[]`). Grounded against Charts.js after the v1.6.0 x-log
diff landed. Pipeline: coder -> reviewer -> qa (planner grounding is below).

## The bug (one gap, both axes)

A log domain whose data spans zero -- `min <= 0, max > 0` -- renders fine but
NaNs the FIRST pan/zoom gesture. It is fail-closed (no wrong pixels; the view
just refuses to move), and it is identical on x and y. v1.6.0 shipped x-log
with this documented as deferred; this patch closes it on both axes together.

### Why it happens

The reactive scale effect floors the domain to its positive part for RENDER,
but the pan/zoom bounds snapshot keeps the RAW (possibly non-positive) min.

- `_dataDomain.{xMin,xMax,yMin,yMax}` is written at **Charts.js:4662-4667**
  from the raw extents `dxMin/dxMax` (x) and `yBase[0]/yBase[1]` (y) --
  BEFORE any log floor.
- The render floor lives in locals only: x in `xlo/xhi`
  (**Charts.js:4691-4701**), y in `lo/hi` (**Charts.js:4723-4732**). Neither
  is written back to `_dataDomain`.
- Gesture math reads `_dataDomain` and takes `log10` of the bound:
  `axisSpan(_dataDomain.xMin, ..., xLog)` at **5068-5069**,
  `_clampToBoundsLog(newView, _dataDomain, xLog, yLog)` at **5031-5033** and
  **5092-5094**. `log10(min <= 0)` is `NaN` -> the whole view goes NaN ->
  `_clampToBoundsLog` / `axisSpan` propagate it, and the clamp bails.

So the render is correct (map(v<=0)=NaN breaks the segment), but the
data-space bounds used for panning are un-plottable on a log axis.

## The fix

When an axis is log, `_dataDomain`'s min for that axis must be the same
positive floor the render path uses -- computed from the DATA extent
(`dxMin` / `yBase[0]`), NOT the view-overridden `xLo/yLo` (the data domain is
the pan-bounds envelope; it must not inherit the current view).

Sketch (place right after the raw write at 4662-4667, before the render-floor
branches so both stay in sync; or refactor the floor into a small pure helper
and call it for both `_dataDomain` and the scale update):

```js
if (_dataDomain) {
    _dataDomain.xMin = dxMin;
    _dataDomain.xMax = dxMax;
    _dataDomain.yMin = yBase[0];
    _dataDomain.yMax = yBase[1];
    // v1.6.1: a log axis pans in log space; its data-domain bound must be
    // positive or log10() NaNs the first gesture. Floor min to the same
    // positive part the render path uses (only when that axis has a
    // positive extent -- no-positive-extent still throws at mount above).
    if (resolvedXType === 'log' && dxMax > 0 && !(dxMin > 0)) {
        _dataDomain.xMin = dxMax * 1e-9;
    }
    if (yScaleType === 'log' && yBase[1] > 0 && !(yBase[0] > 0)) {
        _dataDomain.yMin = yBase[1] * 1e-9;
    }
}
```

Use the SAME `1e-9` factor and the SAME `> 0` predicate as the render floor
(4699 / 4730) so the pan-bounds envelope and the drawn axis agree exactly.
Do NOT floor `_dataDomain` when `dxMax <= 0` -- that case already throws at
mount via `_logDomainError`, and flooring here would mask it.

### Watch-outs (for the reviewer)

- **Hot path / alloc.** This is in the scale effect (sub-Hz, on data/resize),
  not the per-frame draw. Two comparisons + at most two field writes, zero
  allocation. The linear/time path adds two cold `if`s that are never taken.
- **Fail-closed preserved.** The no-positive-extent throw (4693-4697 /
  4724-4728) still runs and still fires first; this only touches the
  mixed-sign case where a positive extent exists.
- **Do not floor the view.** Only `_dataDomain` (the bounds envelope) is
  floored. `xLo/yLo` may legitimately be a user `setView` value; leave the
  render branch as-is.

## Assertions (qa -- falsifiable)

- A1: line chart, `yScale:{type:'log'}`, data y spanning `[-5, 1000]`, `pan:true`.
  After construction, `chart.view.peek()` bounds and a simulated 40px vertical
  drag both stay finite (no NaN) and the view min is `> 0`. Pre-fix this drag
  NaNs the view.
- A2: same for `xScale:{type:'log'}` with x spanning `[-5, 1000]`, horizontal
  drag. (x/y symmetry.)
- A3: a purely-positive log domain (`[1, 1000]`) is byte-unchanged -- the new
  `if`s are not taken; existing v1.6.0 pan/zoom tests still pass verbatim.
- A4: a no-positive-extent log domain (`[-10, -1]`) STILL throws at mount with
  the `_logDomainError` message (the floor must not swallow it).
- A5: zoom (wheel) on the A1 chart also stays finite (covers `axisSpan` at
  5068-5069, not just `_clampToBoundsLog`).
