>> RELEASE -- v1.18.0

Reactive, zero-GC charts.
Sub-frame budget at 100,000 points.

Single-file ESM. Three peer deps (two more optional, injected -- never imported). Signal-native data, dimensions, theme, and series visibility. The hot path is allocation-free; per-frame work is two O(n) scans plus a min/max decimation kernel. The live chart below streams at 30 Hz with crosshair + tooltip -- hover it.

// interpolation

Seven ways to draw a line.

Same 16 samples, seven path-interpolation modes. Linear is honest about data resolution; step variants suit discrete events; monotone smooths without overshooting; catmull-rom is for aesthetics. Hover any cell -- every crosshair syncs.

// multi-series

Click any legend item.

Four series with markers, click-to-toggle visibility, and auto y-axis rescaling. Each row is keyboard-accessible (Tab + Space). When a high series is hidden, the y-domain collapses to fit the remaining data -- the polish lift that surfaces detail when you need it.

// bar chart -- new in v1.1

Categorical data. Grouped layout.

Band scale primitive with d3-style paddingInner / paddingOuter. Multi-series renders grouped side-by-side; each bar takes a slice of the band centered on its series index. Hit detection is O(1) via Math.floor over the band step -- no bisection needed because the discriminator is discrete. Click the legend to toggle a series; the y-domain snaps to fit what's visible.

// horizontal bars -- new in v1.5

Rankings read better sideways.

orientation: 'horizontal' puts the category band on the Y axis (category 0 at top) and grows each bar from the value baseline along X. Long category labels get the horizontal room they need instead of being rotated or truncated under a vertical axis. The vertical draw path is byte-for-byte unchanged -- horizontal selects a peer draw function once at setup, so there is zero per-frame branch and no cost to charts that stay vertical.

Interactive since v1.8.0: drag pans and the wheel zooms the VALUE axis (screen-X here) around the cursor value; the band axis stays pinned -- panning categories is a non-gesture by design. The value grid works too. And since v1.9.0, shift+drag brushes a value range crossed with a band set, emitting a payload DISTINCT from the vertical rect brush: { valueMin, valueMax, bandMin, bandMax, bands, ids } -- category keys, not free y-coords. Still fail-closed where it matters: a log value axis on a horizontal bar throws at construction.

brush: null (shift+drag the bars)
// stacked bar -- new in v1.1

Composition over time.

Same kernel as the grouped bar, with stack: true flipping the layout. Each series gets per-category stackBottoms / stackTops in DATA space, computed by a postExtract hook the kernel runs after every series is extracted. The y-domain rolls up automatically to the cumulative total; hiding a series via the legend rebuilds the stack without that contribution and the surviving segments snap down to fill. Rounded corners apply to the top of each bar; the topmost segment in the stack is the only one whose rounding is visible (lower segments get visually capped by the segment above).

// pie + donut -- new in v1.2

Parts of a whole.

A separate kernel from line/area/bar: createBasePolarChart over slice geometry (no axes, no scales). Angles are stored as Float64 cumulative sums; hit detection is O(n) atan2 inside the ring. Click any legend entry to hide a slice -- the others grow to fill the gap. Pie and donut share the renderer; only the innerRadius default differs (0 vs 0.5; user-overridable). Pie bundle alone is ~13 KB minified -- importing it pulls in no axis-chart code.

New in v1.5: the donut takes a centerLabel -- a live number in the hole, rendered as a DOM overlay (not canvas text) so CSS clamp() sizes it. The chart writes only the hole radius and the label's digit count as custom properties on data/resize; the font fits itself, shrinking as the number grows. Hit "scale x100" -- the total jumps to six figures and the font steps down to stay inside the ring, with zero per-frame JS and no measureText.

total: 9,800 sessions
// bubble -- new in v1.2

Three dimensions in one glance.

A new BUBBLE_RENDERER on the axis kernel. x and y are linear scales as usual; a third dimension drives the bubble's area via a sqrt scale (Tukey convention: equal pixel-area per equal data magnitude). Pixel radii are computed at extract time from r = sqrt(rMin² + t · (rMax² - rMin²)). Hit detection is O(n) distance-from-center inside each bubble, smallest-on-top so overlaps surface the visually-front circle. Bubble bundle is ~22 KB minified -- importing it pulls in zero polar code.

// dense bubble -- spatialIndex x lite-delaunay 1.1.0

2000 bubbles, indexed hit-test.

Past about a thousand points the linear-scan hit-test starts to feel slow. The pluggable spatial-index layer takes any function matching SpatialIndexFactory as the spatialIndex config option, and lite-charts builds an index lazily on the first hit-test, caches it across queries, disposes on data change. This page wires the real default: @zakkster/lite-delaunay 1.1.0's createSpatialIndex -- a pooled, zero-allocation-per-query uniform-grid k-NN index that matches the contract directly, no adapter. One factory serves this chart AND the scatter below (pooled slots, independent dispose). Below the threshold (default 1000 points) the chart stays on the linear-scan path -- on small clouds, the build cost would dwarf the query savings.

// scatter -- new in v1.2-alpha

Just points. Lots of them.

Bubble's simpler sibling: no size dimension, every marker the same pixel radius. Same axis kernel; the spatial- index foundation from alpha.0 works here too, but with k = 1 in findNearest since scatter has no overlap concerns. This plot has 800 points in two visible clusters -- the hit-test still snaps to the nearest within a configurable hitTolerance disc.

// voronoi cells -- cells x lite-delaunay 1.3.0

Every point owns a region.

The same scatter, tessellated. Pass cells: { index: createCellIndex(N) } and each primary-series point owns a bbox-clipped Voronoi polygon drawn UNDER the markers -- geometry from the REAL published @zakkster/lite-delaunay 1.3.0 createCellIndex, injected exactly like spatialIndex (lite-charts imports no implementation). A per-point colorKey tints each cell by its cluster, and hitTolerance: 'nearest' makes the whole plot each point's hit region -- the hover highlight strokes exactly the cell you are inside. Cells are pixel-space and rebuilt with the projection, so pan/zoom never serves a stale polygon.

// field raster + contours -- field x lite-delaunay 1.3.0

The weather map under the dots.

Scattered samples of a continuous scalar. Pass field: { index: createFieldIndex(N), value: 'z' } and the primary series' per-point values rasterize into a smooth barycentric-interpolated heatmap UNDER the markers -- the mesh and grid sampler injected from the published @zakkster/lite-delaunay 1.3.0 createFieldIndex, third rung of the injection ladder. field.contours: { levels: 10 } adds iso-value lines over it: an exact sweep of the same triangulation (edge interpolation, EXACT for the piecewise-linear interpolant -- no marching-squares staircase), stroked between the raster and the dots at 0 B/frame. Drag to pan, wheel to zoom: the raster resamples and the count-form levels re-derive from the FINITE cells in view, so a panned-out extreme never pins the ramp or the levels. Outside the convex hull both layers honestly paint nothing.

// multi-series bubble -- new in v1.2-alpha

Three series, one size domain.

Multiple bubble series rendered on the same axes. The renderer's postExtract hook computes a GLOBAL size domain across visible series, so a value of 30 renders at the same pixel radius in series A as in series B. Toggle any series via the legend -- the global domain recomputes from the surviving series and the bubbles resize accordingly. Hit-test iterates all visible series and reports which series the cursor landed on via the new snapSeriesIdx field.

// per-point color -- new in v1.2-alpha

Every point its own color.

Set colorKey and each row carries its fill color in the data. CSS-var values ('--c-emerald') resolve once at extract time so the per-frame draw still uses a single string assignment per bubble -- no parsing on the hot path. Use this to encode a categorical dimension orthogonal to x / y / size.

// heatmap -- v1.2.0

A fourth, independent kernel.

createHeatmap rides a createBaseGridChart kernel -- no axes, no scales, no interpolation, no markers. Two band scales (x + y), a flat Float32Array for cell values, a Uint8Array presentMask for sparse data, and a precomputed string array for cell colors so the draw loop stays allocation-free. ~11 KB minified -- the smallest of the nine chart bundles. v1.2.0 polish on display: showValues with valueLabelColor: 'auto' picks black or white per cell from NTSC luminance so labels stay readable across the whole ramp; hovering fills row + column highlight stripes (both default on, individually disable-able) before the cell stroke. Hit-test is O(1).

// heatmap, quantile -- v1.2.0

When outliers wash out the rest.

Same data, same ramp, but with colorScale: 'quantile' and colorBins: 6. Quantile binning splits cells into N bins by RANK so each bin has roughly the same number of cells. Hot spots no longer pull the mid-range cells toward the bottom of the ramp; you can compare relative ordering across the whole grid instead of just spotting the extremes. Bin colors are pre-computed from the same two-stop ramp at extract time -- the draw loop stays just fillStyle = cellColors[i]; fillRect(...).

// log scale -- v1.4.0-alpha.0

When linear flattens the small.

Opt in with yScale: { type: 'log' }. The same data plotted twice below: linear on the left crushes the first three orders of magnitude against the axis; log on the right spreads them evenly so every decade gets the same vertical space.

Tick generation routes through lite-axis.logTicks (decade boundaries 1, 10, 100, ...); the map / invert path uses Math.log / Math.exp with cached slope + intercept so per-point projection stays a single multiply-add after one log call. Non-positive values return NaN from map; line / area break the segment, markers skip.

// x-axis log scale -- v1.6.0

Now the other axis, too.

As of v1.6.0 the same opt-in works on x: xScale: { type: 'log' }, on the continuous kernels (line / area / scatter / bubble). The classic reason is a Bode-style response: a low-pass magnitude sampled across five decades of frequency. On linear x the whole audible band is crushed into the left edge; on log x the rolloff reads as the shape it is.

Symmetric with the y-axis: decade ticks via lite-axis.logTicks, log-space pan/zoom, and map(x <= 0) = NaN. Fail-closed -- a non-positive x-domain throws at mount, and xScale: { type: 'log' } on a categorical (bar) or time x-axis throws at construction.

// pan + zoom -- v1.4.0-alpha.2

Drag to pan. Wheel to zoom.

Opt in with pan: true and/or zoom: true. Either flag allocates the view signal and attaches the listener cluster; neither set = no view, no listeners, zero cost. Cursor-anchor convention throughout: the data point under the cursor at gesture start stays under the cursor as you drag.

chart.view is a reactive facade mirroring chart.crosshair -- chart.view() reads (tracks), .peek() reads untracked, .set(v) writes a view object ({ xMin, xMax, yMin, yMax } with any field nullable to fall back to data domain), .reset() clears back to null. The view shape is intentionally symmetric with lite-camera-max's camera signal so the same value drops into a future lite-gl project function unchanged.

Below, the same signal-sourced dataset rendered two ways. Left chart has pan: true, zoom: true, panBounds: 'data' (default) -- pan and zoom stay within the data domain. Right chart has panBounds: 'free' -- you can pan past the data on either axis.

panBounds: 'data' (default) -- clamped to data
panBounds: 'free' -- can extend past data
view: null (following data) | view: null (following data)

// brushing -- v1.4.0-alpha.3

Shift+drag selects. Other charts react.

Opt in with brush: true. Shift+drag selects a rectangle on the top chart; chart.brush emits { xMin, xMax, yMin, yMax, ids }. Below it, two follower charts subscribe to that signal through effect() -- the bar chart shows distribution within the brushed range, and the second line chart highlights only the brushed points. Shift+click (without movement) clears the selection. Coexists with pan/zoom; bare drag still pans.

The cross-chart linking pattern: any effect() that reads chart.brush() re-runs live during the drag, so follower charts update in real time. The ids array is freshly allocated per commit -- no aliasing across brushes.

// annotations -- v1.7.0

Marks that live in data space.

config.annotations takes line / range / point / text marks pinned to DATA coordinates -- an SLO rule at y = 4.5, a shaded deploy window, a labeled incident peak. They re-project through the live scales on every scale change, so pan or zoom the chart and the marks track their data, not their pixels. Rendered above the series, below the crosshair; included in exportSVG; CSS-var colors re-resolve on theme switch.

The config accepts a static array or a () => Annotation[] thunk -- this one reads a signal, so the toggle button below swaps the annotation set reactively. Fail-closed: an entry with a non-finite coordinate draws nothing and throws nothing.

// time series -- v1.10.0 + v1.11.0

Time-first, with the market's gaps shaded in.

createTimeLineChart is createLineChart with time-first defaults: the x-scale is FORCED to 'time' (a conflicting explicit type throws), panBounds defaults to 'data', and opt-in shading paints closed time as range bands on the v1.7.0 annotation layer -- zero per-frame allocation, regenerated on data change, never per pan frame.

Left: shading: true -- one band per Sat-00:00 -> Mon-00:00 UTC span. Right, v1.11.0: sessions: [{ openMinutes: 810, closeMinutes: 1200 }] (13:30-20:00 UTC = NYSE 09:30-16:00 ET) shades the COMPLEMENT of the open-interval union -- after-hours and weekends merge, so Fri-close -> Mon-open is ONE contiguous band. Everything is epoch-ms UTC; converting local session times is the caller's job, and overnight (close < open) sessions throw by design. Both charts pan and zoom -- drag around and the bands track.

shading.sessions -- non-trading time (v1.11.0)
// legend virtualization -- v1.12.0

200 series. 14 legend rows in the DOM.

A legend with hundreds of series used to put one node per series into layout. legend.virtualize hands the row WINDOWING to a caller-supplied adapter -- lite-charts contains zero references to any windowing library (same injection pattern as spatialIndex). This page wires it to @zakkster/lite-virtual's mountList via a ~20-line bridge (view source): the adapter owns row creation and position, the chart owns row contents, and a recycled row re-reads color + visibility on every bind so it never shows stale state.

Scroll the legend, click rows to toggle series, then check the counter -- the DOM row count stays put at window + overscan while count is 200. Listeners and effects stay O(1) too: one delegated click listener, one shared visibility effect, exactly 4 disposers at any series count. Trade-off, documented: keyboard focus does not survive a row scrolling out of the pool.

// svg export -- v1.3.0

Every chart, also a static SVG.

chart.exportSVG(opts?) returns a complete <svg>...</svg> string with xmlns, viewBox, width, and height -- droppable into HTML pages, PDFs, image-converter pipelines, or diffable test fixtures. Implementation is a Canvas2D-shaped shim that walks the live scene tree the same way lite-scene's drawNode does, so the chart's draw callbacks don't know they're rendering to SVG -- pixel-identical to canvas paint (minus DPR scaling; SVG is resolution-independent).
